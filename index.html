02 / Business Analysis Highlight — Real Project Specification

Defining AI Package Quota Architecture & Immutability Rules

One of the trickiest product decisions in Hokori was governing how AI usage credits are consumed by Learners and managed by Admins without breaking fairness or data integrity. Below is the actual specification finalized across Backend, Frontend, and Admin layers:

DECISION 01

Shared AI Quota Pool (Not Split by Service)

Instead of fragmenting quotas across Grammar, Kaiwa, and Conversation, each AI package defines a single TOTAL_AI_QUOTA, duration, and price. Every AI request deducts 1 shared credit with no multiplier.

  • Backend impact: Single quota counter per purchase; no per-service_code tracking overhead.
  • Frontend impact: Clean UI showing only Remaining AI Credits in AiQuotaOverview.
  • Admin impact: Simplified package creation with one unified quota field.
DECISION 02

CRUD Immutability & Commercial Fairness

Once a package has been bought (purchase_count > 0) or used (usage_count > 0), it is treated as a locked contract.

  • Edit Rule: Allowed only when INACTIVE AND purchase_count = 0 AND usage_count = 0.
  • Deactivate / Delete Rules: Cannot deactivate-to-edit or delete packages with existing buyers/usage (soft-delete only when unused).
  • Promotion Rule: Price/quota changes require creating a new package while existing buyers retain their original terms.
EXCERPT FROM LEARNER BUSINESS RULES (BR-LR series) Enforced across Frontend UI validation and API guards
Rule ID Domain Business Constraint & Verification Scope
BR-LR-04 / 10 Enrollment & Payment Paid course access is granted only after payment completion; failed or cancelled payments never activate enrollment.
BR-LR-13 / 15 JLPT Mock Test Each test start creates a fixed-duration session; learners can view only their own exam history and results.
BR-LR-17 / 18 AI Quota Gating AI features are accessible only within active package quota; exhausted quota blocks requests until renewal.
BR-LR-20 Exam Integrity AI assistance is strictly prohibited during active JLPT mock test sessions to prevent cheating.

03 · Independent Micro-SaaS Product · Live in Production

RatioPack Batch Pro — Etsy Print Ratio Batch Processor

Solo Product (2026) · Role: Product Designer, Business Rules & Full-Flow Builder (ReactJS, TypeScript)

A live 100% client-side web utility built for Etsy digital wall-art sellers to convert high-resolution artwork into 5 standard 300 DPI print ratios (2:3, 3:4, 4:5, 11×14, ISO A), automatically split into ≤ 18 MiB ZIP parts to stay safely below Etsy’s 20 MB upload cap without uploading user files to any server.

Product Analysis & Commercial Rules

  • Entitlement & Anti-Abuse Architecture: Designed Free (1 artwork/run) vs. Pro (unlimited batch) rules backed by a Vercel serverless endpoint (POST /api/verify-license): ECDSA P-256 server-signed Pro tokens, a 10-device activation cap, 7-day silent token renewal, and automatic Pro revocation on Gumroad refunded, chargebacked, or disputed states.
  • Conversion & UX Iteration: Removed user drop-off points by preserving the free processed image when closing the upgrade modal, adding live center-crop ratio previews before export, writing plain-language error messages, and publishing a standalone Etsy Print Size Guide.
